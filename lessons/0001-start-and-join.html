Start and Join

Give work to another thread, wait for it, and read the answer.

Your win today: you'll write the two missing lines in a program that sums 10 million numbers on two threads, and see it print PASS. About 20 minutes.

Almost every example in ElementaryParallelism follows this pattern, and so will the Java assignment and the exam's coding questions. Look at Deck 1, slide 17: // wait for search to end. That comment stands in for the line of code this lesson teaches.

1 · Process and thread

Deck 1 · slides 8, 12, 38–41

A process is a running program with its own memory. A thread is one path of execution inside a process. Every Java program starts with one thread, the one running main, and you can add more.

Oracle's tutorial: “Threads exist within a process — every process has at least one. Threads share the process's resources, including memory and open files.” Processes and Threads

For this course, one fact matters most (slide 41):

  • Shared: objects and their fields. If two threads hold a reference to the same array, they see the same array.
  • Private: local variables. If two threads run the same method, each gets its own copy of the locals.

2 · Creating a thread

Deck 1 · slides 42–48

Put the work in a method called run(). There are two ways to do that:

// Way A: extend Thread
class Worker extends Thread {
    public void run() { /* the work */ }
}
Thread t = new Worker();

// Way B: implement Runnable, then hand it to a Thread
class Job implements Runnable {
    public void run() { /* the work */ }
}
Thread t = new Thread(new Job());

Either way, nothing happens yet. You have only created a Thread object.

Oracle recommends Runnable because your class can still extend something else, and because the thread pools in Deck 2 take Runnables. Defining and Starting a Thread

3 · start(), not run()

t.start();  // new thread runs run(); returns at once
t.run();    // NO new thread: main runs it, a normal call

This is the classic exam trap. run() is just a method. Only start() creates a new thread, and a thread can be started only once: a second start() throws IllegalThreadStateException.

From the Javadoc: run() “is not intended to be invoked directly”, and start(): “A thread can be started at most once.” java.lang.Thread

4 · join(): wait for it

Deck 1 · slides 57–58, 75–79

Once started, the new thread and main run at the same time. The scheduler decides who goes when, and you can't predict it (slide 41). So if main wants the result, it has to wait:

t.start();
t.join();   // main pauses until t has finished
System.out.println(t.getResult());  // now safe
“t.join() causes the current thread to pause execution until t's thread terminates.” Oracle: Joins. join() can throw InterruptedException, which is why the slides wrap it in try/catch. Writing throws InterruptedException on main also works.

Without the join(), main reads the result while the worker may still be running, and usually gets the default value 0. Nothing crashes; you just get the wrong number.

The slides call this pattern (a thread that computes something, then join, then getResult()) an asynchronous procedure (slides 75–79).

5 · The pattern

Deck 2 · slides 2–4

Put it together and you have the backbone of Deck 2:

  1. Split: give each worker its own range, e.g. [0, mid) and [mid, n).
  2. Start all: call start() on every worker before joining any of them.
  3. Join all: wait for each one.
  4. Combine: read each getResult() and merge them (add, OR, merge-sort…).

Order matters in steps 2–3. a.start(); a.join(); b.start(); b.join(); is correct but serial: b doesn't begin until a has finished. Deck 2 slide 87 shows the same mistake with Fork/Join (“Never do this!”).

Check yourself

Answer from memory, without scrolling up. You get one click per question.

Thread t = new MessagePrinter("hi", 3); then t.run();. Which thread prints "hi"?

run() is an ordinary method call, so main executes it. Only start() creates a new thread.

Take Deck 1 slide 58 and delete the t.join(). Where does “All messages are printed” appear?

Without join(), the two threads run concurrently and the scheduler chooses the order. It's often first, because main is already running, but nothing guarantees that.

Which method calls, in which order, run two workers in parallel and then wait for both?

Start everything, then join everything. Joining a before starting b makes the program serial. run() creates no threads. Joining a thread that hasn't been started returns immediately, so the last option doesn't wait for any work.

What happens when you call t.start() a second time on the same thread?

IllegalThreadStateException. A thread can be started at most once, even after it has finished.

Two threads both run the same run(), which declares a local int k = 0;. What happens to k?

Each thread has its own stack, so locals are private (Deck 1 slide 41). Fields of a shared object are what threads share.

Stretch: break it on purpose

(a) Remove only the joins. What prints, and why? (b) Swap start() for run(). It still prints PASS. Why is that a bad sign rather than a good one?

Solution (only after trying) 
left.start(); right.start();
left.join();  right.join();

(a) total = 0: main reads the results before the workers have written them. (b) run() makes main do both halves one after the other. The answer is correct but nothing ran in parallel, so the output alone can't tell you whether you used threads.

What are the four steps of the pattern?

Split → start all → join all → combine.

What's the difference between start() and run()?

start() creates a new thread that executes run(). Calling run() directly is a normal method call on the current thread.

What do two threads share, and what is private to each?

Shared: objects and their fields (and statics). Private: local variables, because each thread has its own stack.
