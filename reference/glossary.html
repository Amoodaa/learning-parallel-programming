Glossary

The words every lesson uses, with one meaning each.

Terms are added as lessons cover them. Where the slides use several words for the same thing, this page picks one.

Threads

Process
A running program with its own private memory space. Contains one or more threads.
Thread
One path of execution inside a process. It has its own stack and shares the process's heap with the other threads.
Avoid: “lightweight process”, “task” (task means something else once thread pools arrive)
Main thread
The thread the JVM creates to run main(). Every program has one.
Start
Calling start(), which creates a new thread that runs the object's run(). Calling run() directly does not start anything.
Join
Calling t.join(): the current thread waits until thread t terminates.
Avoid: “wait for” as a technical term (wait() is a different method, coming in a later lecture)
Asynchronous procedure
A thread that computes a result and exposes it through a method like getResult(), to be read after a join (Deck 1 s75).
Scheduler
The part of the OS/JVM that decides which thread runs on which core, and for how long.
Concurrent
Two threads are concurrent if their executions can overlap, so either could run first (Deck 1 s9).
Parallel
Two threads are parallel if they are actually executing at the same instant, on different cores. Parallel implies concurrent, not the other way round.
Sleep
Thread.sleep(ms): pauses the current thread for a time. Static, whatever object you call it on.
Interrupt
A signal from one thread asking another to stop what it's doing. A sleeping thread receives it as an InterruptedException.
Thread state
One of NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED, returned by getState().
Stop flag
A volatile boolean field that a thread's run() loop checks, and that another thread sets to end it cleanly.
Volatile
A field modifier guaranteeing that a write by one thread is visible to later reads by other threads. Gives visibility, not mutual exclusion.
Non-deterministic
The same program, with the same input, can produce different output on different runs, because the scheduler interleaves threads differently.

Sharing & deadlock

Critical section
Code that uses a shared resource and must not be run by more than one thread at a time.
Mutual exclusion
The guarantee that at most one thread is inside a given critical section.
Race condition
A bug where the result depends on how threads happen to interleave, e.g. two unsynchronised count++.
Avoid: “sharing violation” (the slides' term for the same thing)
Atomic
Happens as one indivisible step that no other thread can see half-done. count++ is not atomic.
Deadlock
A set of threads, each waiting for an event that only another thread in the set can cause.
Coffman conditions
Mutual exclusion, hold and wait, no pre-emption, circular wait. All four are needed for deadlock.
Starvation
One thread waits forever while the others keep making progress.
CPU-bound / I/O-bound
A thread that spends its time computing / waiting on disk, network or a user.
