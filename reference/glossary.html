Glossary

The words every lesson uses, with one meaning each.

Terms are added as lessons cover them. Where the slides use several words for the same thing, this page picks one.

Threads

Process
A running program with its own private memory space. Contains one or more threads.
Thread
One path of execution inside a process. It has its own stack and shares the process's heap with the other threads.
Avoid: “lightweight process”, “task” (task means something else once thread pools arrive)
Main thread
The thread the JVM creates to run main(). Every program has one.
Start
Calling start(), which creates a new thread that runs the object's run(). Calling run() directly does not start anything.
Join
Calling t.join(): the current thread waits until thread t terminates.
Avoid: “wait for” as a technical term (wait() is a different method, coming in a later lecture)
Asynchronous procedure
A thread that computes a result and exposes it through a method like getResult(), to be read after a join (Deck 1 s75).
Scheduler
The part of the OS/JVM that decides which thread runs on which core, and for how long.
Concurrent
Two threads are concurrent if their executions can overlap, so either could run first (Deck 1 s9).
Parallel
Two threads are parallel if they are actually executing at the same instant, on different cores. Parallel implies concurrent, not the other way round.
Non-deterministic
The same program, with the same input, can produce different output on different runs, because the scheduler interleaves threads differently.
